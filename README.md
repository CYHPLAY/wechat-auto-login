# wechat-auto-login

微信 PC 版开机自动登录工具 —— 开机登录 Windows 后，由一个**“登录时触发”的计划任务**立即运行脚本：自动启动微信，**先检测绿色“进入WeChat”按钮是否就绪再点击**（通常 1 次命中），实现进桌面即自动登录。**不多开、不固定干等、不受开机启动延迟影响。**

## 功能

- **登录计划任务，开机最快**：自启使用 Windows 任务计划程序的“**用户登录时**”触发器，由系统计划服务在登录瞬间直接拉起，**不受启动文件夹 / 注册表 Run 项约 10 秒的“开机启动延迟”影响**（这是过去“进桌面好久微信才出来”的主因）
- **唯一开机入口、绝不三开**：`setup.ps1` 会自动清理其它重复来源——启动文件夹里直接启动微信的快捷方式、注册表中微信自带的开机自启；只保留这一个计划任务
- **幂等启动**：检测到微信进程已在开机初始化，就只等待、**绝不重复启动**；只有进程不存在时才启动一次。进程驻留托盘、没有可见窗口时，按“先宽限 12 秒、之后每 8 秒最多一次”节流唤起，防止多开
- **不写死用户名**：登录触发器不绑定具体账户（任何用户登录都会触发），运行身份由系统在部署时自动设为当前登录用户；脚本文件里不含任何用户名 / 计算机名，拷到别的电脑直接可用
- **开机即跑、无固定睡眠**：登录窗 / 绿色按钮一就绪就动作，不用 `Start-Sleep` 干等
- **检测之后再点击**：用 `GetPixel` 读取按钮区域 9×3 个像素的颜色，确认绿色按钮已渲染就绪才点击；**按钮没就绪时鼠标完全不动、不空点**。不截屏、不保存图片、不做图像 / 模板匹配
- **点击后校验**：确认渲染窗由竖版（登录）变为横版（主界面）才算成功；万一没进入则重新检测再点，默认最多补点 5 次
- **鼠标自动归位**：仅真正点击时移动指针，登录完成后移回原位
- **不挑界面语言**：按“微信进程 + 自绘渲染窗 `MMUIRenderSubWindowHW`”定位，中文“微信”/英文“WeChat”通吃
- **零第三方依赖**（纯 PowerShell + Windows user32/gdi32 API）
- **分辨率 / DPI / 安装位置自适应**：自动识别微信路径与物理分辨率，按钮按窗口比例定位
- **一键部署 / 一键卸载**：`setup.ps1` 一键配置并去重；`uninstall.ps1` 干净移除计划任务

## 原理

微信登录界面是自绘 UI（MMUI/Qt），**没有标准按钮句柄、查不到按钮“可点”状态、也不接受后台消息注入**，只能用真实鼠标点击。脚本流程：

1. **幂等启动**：有微信进程（开机自启正在初始化）就只等待；没有进程才 `Start-Process` 启动一次
2. 定位竖版登录窗（属于微信进程、可见、含 `MMUIRenderSubWindowHW` 且为竖版；**不依赖窗口标题语言**），等矩形稳定。进程在但无窗时按节流规则唤起，避免与微信自带启动叠加
3. **取色检测**：在按钮区域（按窗口比例定位，约渲染区 49.8%、77.3% 为中心）采 9×3 个像素，统计“微信绿”占比，达到阈值（默认 30%）才判定就绪；此阶段不移动鼠标，采样能避开按钮中央白色文字
4. 置前窗口、产生一次 hover，真实鼠标点击一次
5. 轮询校验是否变为横版主界面：是则成功；否则回到第 3 步重新检测再点（默认最多 5 次）
6. 鼠标归位并退出

**为什么用计划任务而不是启动文件夹**：Windows 对“启动文件夹”和注册表 `Run` 里的程序，开机登录后会统一延迟约 10 秒再启动（Startup Delay），导致脚本和微信都被推迟。任务计划程序的“用户登录时”触发器由计划服务直接调度，**没有这段延迟**，登录即跑。

> 提示：请在微信登录时勾选**“自动登录该设备”**（手机端），点击“进入WeChat”后即可免手机确认。

## 使用

### 一键部署（推荐）

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
```

自动完成：识别微信路径 → 识别物理分辨率 → 生成脚本（UTF-8 带 BOM）→ 清理重复开机启动 → 创建计划任务 **`WeChatAutoLogin`**（用户登录时触发，无启动延迟）。

### 立即测试 / 手动运行

```powershell
# 方式一：手动触发一次计划任务（和开机自启走同一条链路，推荐这样测）
Start-ScheduledTask -TaskName 'WeChatAutoLogin'

# 方式二：直接运行主脚本
powershell -NoProfile -ExecutionPolicy Bypass -File wechat_autologin.ps1

# 仅（重新）创建开机计划任务
powershell -ExecutionPolicy Bypass -File install_autostart.ps1
```

### 卸载（移除开机自启）

```powershell
powershell -ExecutionPolicy Bypass -File uninstall.ps1
# 或手动：Unregister-ScheduledTask -TaskName 'WeChatAutoLogin' -Confirm:$false
```

卸载只删除本项目的计划任务和相关快捷方式，不影响其他软件；不会自动恢复微信自带开机项（需要时在微信 **设置 → 通用设置 → 开机自动启动** 重新勾选）。

## 参数

`wechat_autologin.ps1`：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-WeChatExe` | `D:\WeChat\Weixin\Weixin.exe` | 微信程序路径（`setup.ps1` 自动识别并替换） |
| `-WeChatDir` | `D:\WeChat\Weixin` | 微信工作目录 |
| `-WindowTimeoutSec` | `30` | 等待竖版登录窗出现的超时（秒） |
| `-ButtonTimeoutSec` | `60` | 等待绿色按钮就绪的超时（秒，开机网络慢可更长） |
| `-BtnX` / `-BtnY` | `0.498` / `0.773` | “进入WeChat”按钮中心相对位置（点不准时可微调） |
| `-GreenRatio` | `0.30` | 采样像素中绿色占比达到该值即判定按钮就绪（误判调大、检测不到调小） |
| `-MaxRetries` | `5` | 检测到绿并点击后，若没进入主界面的最多补点次数 |
| `-MinReadyMs` | `250` | 登录窗矩形稳定后至少等多久再开始取色（毫秒） |
| `-ReviveGraceSec` | `12` | 进程在但无窗时，先宽限多久再唤起（给开机初始化留时间） |
| `-ReviveIntervalSec` | `8` | 两次唤起微信之间的最小间隔（节流，防止多开） |
| `-RestoreMouse` | `$true` | 登录完成后是否把鼠标移回原位 |
| `-DontLaunch` | 开关 | 加上则完全不主动启动/唤起微信（只等待并点击，适合你想保留微信自己的开机启动时） |

## 注意事项

- **为什么以前开机慢 / 开多个微信**：① 启动文件夹 / `Run` 项有约 10 秒开机启动延迟；② 微信自带开机启动（注册表 `Run` 的 `Weixin -autorun`）、启动文件夹快捷方式、自动登录脚本三者会同时拉起微信。重新运行一次 `setup.ps1` 即改用“登录计划任务 + 脚本幂等启动”，既省掉启动延迟，也只保留一个入口。
- **耗时构成（实测，仅供参考）**：计划任务触发到微信进程出现约 0.5～1 秒（含 PowerShell 冷启动），登录窗约 1～2.5 秒出现，绿色按钮就绪后通常 **1 次**点中；点击后微信还需约 4～5 秒完成登录验证、加载主界面（**与网络/机器性能有关，脚本无法压缩**）。开机磁盘/CPU 紧张时这些时间会更长，属正常现象。
- 脚本**只在检测到绿色按钮、真正点击的瞬间**移动鼠标，检测阶段鼠标不动；登录后自动归位（`-RestoreMouse $false` 可关闭）。
- “自动登录”需先在**手机端**勾选“自动登录该设备”；只建议在自己的常用电脑上启用。
- 按钮按**相对比例**定位，不同分辨率 / DPI 可直接使用；偏差用 `-BtnX`/`-BtnY` 微调，绿色判定用 `-GreenRatio` 微调。
- **检测方式与隐私**：不截屏、不保存图像、不做图像识别，仅用 `GetPixel` 读取按钮区域 27 个像素的颜色值判断是否变绿，不读取聊天内容或其他界面。
- 计划任务以**当前登录用户、交互会话、普通权限**运行（不弹 UAC、不需要管理员）；笔记本用电池也会运行。

## 编码说明

- 脚本含**中文注释**，需使用 **UTF-8（带 BOM）** 编码保存。
- `setup.ps1` 生成的 `wechat_autologin.ps1` **自动带 BOM**，Windows PowerShell 5.1 下不会乱码。
- 手动编辑后若在 PowerShell 5.1 出现乱码：记事本“另存为”→ 编码选 `UTF-8（带 BOM）`；PowerShell 7 / VS Code 通常无此问题。
